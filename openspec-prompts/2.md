## Detailed Error Fixing Guide

**GOLDEN RULE**: You are fixing DML **SYNTAX ERRORS ONLY**, not rewriting the implementation!
- The existing code contains valuable implementation logic in TODO comments and method bodies
- Your job is to add missing DML syntax elements (like `param offset`, template declarations, etc.)
- Do NOT remove existing code
- Do NOT rewrite methods or logic
- Do NOT remove TODO comments

### Error Type 1: "no assignment to parameter 'offset'"
**What this means**: Registers need offset parameters, which are typically defined in auto-generated glue files.

**How to fix**:
1. Check if the import statement for the glue file is missing
2. Look for imports like `import "<device_name>-glue.dml";` (where <device_name> is your actual device name like wdt, timer, uart, etc.)
3. If missing, add it back near the top of the file, after other imports
4. **DO NOT manually add `param offset` to each register** - this is auto-generated!
5. Example (for a device named "wdt"):
```dml
// Import the DIA (Device Interface Abstract) and generated glue code
import "wdt-dia.dml";
import "wdt-glue.dml";  // ADD THIS LINE if missing - it contains register offsets
import "simics/devs/signal.dml";
```
For other devices, use the appropriate device name (e.g., "timer-glue.dml", "uart-glue.dml", etc.)

**What NOT to do**:
- ❌ Do NOT manually add `param offset = 0x000;` to each register
- ❌ Do NOT remove import statements
- ❌ Do NOT rewrite register definitions
- ✅ ONLY add back the missing import statement

**RAG Query to use**: "DML 1.4 import glue file register offset"

### Error Type 2: "Need to instantiate one of the templates"
**What this means**: Event objects must specify which template they use.

**How to fix**:
1. Find the event declaration (e.g., `event timer_event;`)
2. Add template instantiation: `event timer_event is (simple_time_event);`
3. **DO NOT modify any existing code that uses this event**
4. Example:
```dml
event timer_event is (simple_time_event);  // ADD 'is (simple_time_event)' ONLY
```

**What NOT to do**:
- ❌ Do NOT rewrite methods that call `schedule_event` or other event methods
- ❌ Do NOT change event callback implementations
- ✅ ONLY add the template declaration to the event line

**RAG Query to use**: "DML 1.4 event template simple_time_event"

### Error Type 3: "reference to unknown object 'wdt.bank'"
**What this means**: The code is referencing `wdt.bank` which doesn't exist. It should reference the actual bank object.

**How to fix**:
1. Find references like `wdt.bank.WatchdogRegisters.WDOGLOAD.val = 0xFFFFFFFF;`
2. Look at the DML file structure to find the correct path
3. **ONLY change the object reference path**, keep all other code
4. If the bank is named `WatchdogRegisters`, change to: `WatchdogRegisters.WDOGLOAD.val = 0xFFFFFFFF;`
5. Or if there's a `bank` object, reference it correctly

**What NOT to do**:
- ❌ Do NOT rewrite the entire method containing the reference
- ❌ Do NOT remove the logic around the reference
- ✅ ONLY fix the object reference path

**RAG Query to use**: "DML 1.4 bank register object hierarchy how to reference registers"

### Error Type 4: "unknown identifier: 'schedule_event'"
**What this means**: The event scheduling method name is wrong for the template being used.

**How to fix**:
1. If using `simple_time_event`, use `timer_event.post(dev, seconds_time, NULL);`
2. **ONLY replace `schedule_event(...)` with the correct method call**
3. **DO NOT rewrite the entire method or remove surrounding logic**
4. Replace `schedule_event(...)` with the correct method from RAG

**What NOT to do**:
- ❌ Do NOT rewrite the entire callback or timer method
- ❌ Do NOT remove the method body
- ✅ ONLY fix the event scheduling call

**RAG Query to use**: "DML 1.4 simple_time_event post method"
